# Retrospective — Epic 09: UX / Intent

## Sprint snapshot
- Escopo: 1 epic, 10 stories, 3 sprints — **todas done**.
- Cobertura de testes: 532 pass, 0 fail, 5 skipped (tool contract). `npm run validate` verde (78 files).
- Entregue: block scalar parser fix, intent descriptions (61 files), intent routing (56 intents), onboarding revamp, research dispatcher, sign-scope + guided scope, non-interactive install + honest uninstall, release/changelog skills, CI workflow, metadata hygiene.
- Release: **v0.12.0**.
- Carry-over: 0 stories. 3 HIGH findings from code review remain open (see Notes).

## Worked
- **Block scalar parser fix (S01) desbloqueou tudo.** `readYamlField`/`readFrontmatter` agora lê `|`, `>`, `|-`, `|2` — 11 testes dedicados. As 10 skills de persona não renderizam mais `— |`. Sem isso, S02 e S03 não tinham substrato.
- **Intent descriptions em massa (S02).** 61 arquivos de workflow/skill ganharam `description:` orientado a intenção. O harness agora roteia pelo que o usuário quer, não por fase.
- **Intent routing table (S03).** 56 intents mapeadas em `wize-help`. "quero pesquisar concorrência" → `wize-market-research`. "criar escopo" → `wize-sec-scope`. Teste cobre todas as skills (com exclusions documentadas).
- **Research dispatcher (S04).** `wize-research` classifica e delega para `wize-market-research`, `wize-domain-research`, ou `wize-technical-research`. Pepper's agent.yaml lista todas 3.
- **Non-interactive install (S06).** `--profiles`, `--targets`, `--yes`, `--dry-run` funcionam. `resolveName()` fallback chain: git config → $USER → 'Developer'. Uninstall remove adapters de verdade (não mais stub).
- **CI workflow (S08).** `.github/workflows/ci.yml` roda `npm test` + `npm run validate` em push/PR. Node 20.x e 22.x. Permissions mínimas.
- **Onboarding one-liner (S09).** `onboarding.js` agora retorna ≤3 linhas, sempre termina com `→ /wize`. Contextual (brownfield, security-overlay).
- **Release/changelog skills (S07).** Workflows bem estruturados com pré-requisitos, inputs, outputs, steps, anti-patterns. Keep a Changelog format. Semver bump zero-dep.

## Didn't work
- **`wize-sec-scope` não é descoberto pelo harness (H1, H2).** O skill existe, os testes passam, mas o `agent.yaml` do red-teamer não o declara em `skills:`/`commands:`, e a tabela de intents do `wize-help` não tem entrada para ele. Natasha não consegue invocar scope creation. O código está certo; a integração está quebrada.
- **Typo `sprint_status.yaml` no `wize-release` (H3).** Linha 105 do workflow referencia `sprint_status.yaml` (underscore) em vez de `sprint-status.yaml` (hyphen). Um agente seguindo literalmente escreveria no arquivo errado.
- **Duplicação `wize/skill.md` ≈ `wize-help/skill.md` (M3 da Sprint 1).** O alias duplica 148 linhas do help. Qualquer mudança futura na tabela de routing exige editar dois arquivos. A recomendação de fazer um thin delegation file não foi implementada.
- **`renderAgentsMd` ainda referencia `/wize-help` como primário (M2 da Sprint 1).** Duas linhas no template do `AGENTS.md` ainda usam `/wize-help` em vez de `/wize`. Corrigido parcialmente — o onboarding já mostra `/wize`, mas o template gerado para novos projetos ainda aponta o alias antigo.
- **3 HIGH findings do code review não foram corrigidos antes do fechamento do epic.** O review de Sprint 2+3 marcou CHANGES_REQUESTED com H1, H2, H3. As stories foram marcadas done com os findings em aberto.

## Surprised us
- **61 arquivos de description em um sprint.** A estimativa inicial era de que S02 seria o gargalo do epic. Peggy + Tony entregaram em paralelo com S01 e S03, sem bloquear ninguém.
- **O parser de block scalar pegou 6 variantes YAML que ninguém usa no kit.** `|+`, `>-`, `|2`, `>4` — testados e funcionando, mas zero ocorrências reais. O investimento em completude foi desproporcional ao risco.
- **Tool contract tests (5 skipped) são a única dívida de teste restante.** Os 5 skipped são testes que rodam binários reais (gitleaks, nuclei, etc.) e pulam quando a ferramenta está ausente. O RETRO-1 (smoke opt-in) continua pendente.
- **A review de Sprint 2+3 encontrou 3 HIGHs que o review de Sprint 1 não previu.** H1 e H2 são gaps de integração entre skills que foram desenvolvidas em paralelo (S05 e S03). O processo de review por sprint não detectou a dependência cruzada.

## Decisions made
- `description:` no frontmatter é obrigatório para todo workflow/skill. Validator rejeita ausência.
- `/wize` é o alias primário; `/wize-help` é o canônico. Ambos apontam para o mesmo skill.
- `wize-research` é dispatcher, não skill de pesquisa independente. Delega para as 3 variantes.
- Onboarding pós-install é ≤3 linhas e sempre termina com `→ /wize`.
- `wize-sec-scope` é skill de primeira classe (não só flag do pentest). Precisa estar no agent.yaml e na tabela de intents.
